# Copilot SDK / Node.js

SDK の API を使い、ブラウザー画面からモデル・セッション・会話を操作する JavaScript サンプルです。
Node.js `^20.19.0` または `>=22.12.0` と Copilot のログインが必要です。

## ファイル構成とログ

- `app/server.js`: HTTP API と起動／終了処理。
- `app/copilot.js`: SDK の接続・一覧・会話履歴・モデル切り替え・送信処理。
- `app/pipeline.js`: パイプライン定義の読み込み・手順ごとのモデル更新・実行・合否と消費 AI クレジットの集計。
- `app/pipeline/`: `pipeline.json` と、各手順の `prompt.md`・`verify.md`。
- `app/logger.js`: ターミナルへの通知、SDK イベントログと消費 AI クレジット別ログの保存。
- `app/public/`: React ベースのパイプラインスタジオ画面（HTML・JavaScript・CSS）。`react`・`react-dom`・`htm` はローカルの `node_modules` から配信します。
- `app/tests/`: SDK 処理・パイプライン・HTTP API のテスト。
- `app/logs/`: 新しい実行ログと消費 AI クレジットログ。サーバー関連はすべて `app/` 内にまとめています。

プロンプト送信ごとに `app/logs/server-セッションID-日時-PID.jsonl` を作成します。
また、パイプライン実行時にはイベントログとは別に、消費 AI クレジット専用ログ `app/logs/server-credits-セッションID-日時-PID.jsonl` を作成し、パイプライン 1 手順につき 1 行の JSON（実行・検証・合計の AI クレジットと `totalNanoAiu`、トークン数、使用モデル ID、合否）を記録します。
ログは、送信中に受信した SDK イベントをそのまま JSON にして1行1件保存します。
SDK の ID・時刻・イベント種別・データを保持し、本文の断片、ユーザー入力、確定本文、ツール実行、サブエージェントなどの受信イベントを記録します。
独自の `time/type/data` 包装、一覧取得結果、表示用の改行、独自の最終回答レコードは追加しません。
SDK 自身が送る確定本文のイベントは、本文の断片とは別のイベントとして残します。
一覧・履歴の取得だけでは実行ログを作成しません。
ログ書き込みに失敗した場合は実行を中断してエラーを返します。
ログには会話・コード・ツール引数や結果が含まれる場合があるため、共有や添付の前に確認してください。
`logs/` は Git の管理対象外です。以前のルート直下のログは削除せず残しています。不要なログは手動で削除してください。

テストは `npm test` で実行できます。SDK 通信はモックするため、ログインやモデルへの送信は不要です。

## 起動

```powershell
npm install
copilot login
npm start
```

新規セッションの ID は SDK が生成します。実行したディレクトリで作成され、再開時は保存された作業ディレクトリを使用します。
送信時は料金・クォータが適用される場合があります。応答待ちは最大10分です。
`approveAll` で権限要求を自動許可します。管理ポリシーで自動許可が利用できない場合はエラーになります。
作成・再開ともに `streaming: true` を設定し、生成された本文を画面へ逐次表示します。

## パイプライン実行

`app/pipeline/pipeline.json` に手順を定義し、画面の「パイプライン」から実行します。

```json
{
  "steps": [
    {
      "id": "step1",
      "name": "構成の調査",
      "model": "gpt-6-luna",
      "prompt": "step1/prompt.md",
      "verify": "step1/verify.md",
      "passed": false
    }
  ]
}
```

- `model` にはモデル一覧の `id`（例: `gpt-6-luna`、`claude-sonnet-5.5`、`auto`）を指定します。画面では `/api/models` の一覧から `id` を解決し、モデルの表示名（`name`）で固定表示します。モデルの変更は `pipeline.json` を編集してください。
- `prompt`・`verify` は `app/pipeline` からの相対パスです。外のファイルは参照できません。
- 1 手順につき、指定された `model` に切り替えたうえで `prompt.md` を送信し、続けて `verify.md` を同じ会話へ送信します。
- 検証の回答が `OK` で始まれば合格、それ以外（`NG` など）は不合格です。検証用 `.md` には「1行目を OK または NG で始める」と明記してください。
- 合否は毎手順ごとに `pipeline.json` の `passed` へ書き戻します。途中で止まっても、そこまでの結果は残ります。
- 各手順で消費した AI クレジット（SDK の `assistant.usage` / `toolUsage` の `totalNanoAiu` を 10 億で割った値）を、画面の各手順カードおよび別ログ `app/logs/server-credits-セッションID-日時-PID.jsonl` にパイプライン 1 手順につき 1 件出力します。
- 画面には料金レート `$0.01 = 1 AI Credit` を表示します。消費量は SDK がサーバーから受け取った `totalNanoAiu` を 10 億で割って算出し、モデルのトークン単価から金額を推定していません。
- 不合格になった時点で停止し、以降の手順は実行しません。
- 「開始」「終了」のプルダウンで、途中から途中までの範囲を実行できます。
- ステップ数に上限はありません。全手順を横方向に並べ、画面幅を超えた分はパイプライン欄をスクロールして確認できます。
- 範囲に含めた手順は、すでに `passed` が `true` でも再実行します。
- 範囲内のすべての手順は 1 つのセッションで続けて実行します。画面でセッションを選んでいればそれを再開し、未選択なら新規作成します。
- 実行中の表示は通常の送信と同じで、手順と段階（実行／検証）ごとに `<details>` が分かれます。SDK イベントも同じ形式で `app/logs/` に保存されます。

## ブラウザー画面

```powershell
npm run ui
```

`npm run ui` は `npm start` と同じ起動コマンドです。
起動後、ブラウザーで http://127.0.0.1:3000 を開きます。
セッション一覧とモデル一覧はプルダウンで表示します。「再読み込み」で一覧を更新できます。
セッションは最終更新の新しい順で全件取得し、取得失敗時は画面にエラーを表示します。

- セッションのプルダウンから既存セッションを選ぶと、保存済みの入力・回答・ツール履歴を取得します。履歴取得はモデルへプロンプトを送信しません。
- 過去の履歴は「過去の履歴」の `<details>` にまとめて折りたたみ、件数をバッジで表示します。
- プルダウンの先頭「新規セッション（送信時に作成）」を選ぶと新規作成に切り替わります。セッションの作成は最初の送信時です。
- モデルは新規作成時だけでなく、既存セッションの途中からでもプルダウンで変更して送信できます。
- プロンプトを入力して「送信」すると、回答本文を生成された順に表示します。
- 「パイプライン」から、定義済みの手順をまとめて実行できます（上記参照）。
- 入力ごとに `<details>` でまとめ、実行中でも開閉できます。閉じていても応答の受信とログ保存は続きます。
- ツールの開始・完了・失敗は各入力の「ツール実行」に表示します。完了・失敗も明示し、失敗時は受信済み本文を残します。
- 実行中は重複送信やセッション切り替えを無効化します。別タブからの送信・履歴取得もサーバー側で拒否します。
- 画面との接続が切れた場合は SDK 実行の中断を要求します。

過去の履歴は `getEvents()` で取得します。過去のストリーム断片は SDK の保存履歴に残らないため、確定した本文を表示します。新しい JSONL ログには受信したストリーム断片も残ります。
ファイル編集・コマンド実行は自動許可されます。信頼できる指示だけを送信し、同じセッションを VS Code と SDK で同時に操作しないでください。

サーバーはローカルホストのみに接続を許可し、外部サービスや CDN は使用しません。
HTTP は一覧・履歴の GET と、プロンプト送信の POST のみです。POST の応答は1行1件の JSON を逐次返します（NDJSON）。
画面には文字列として表示し、回答に含まれる HTML やスクリプトは実行しません。ログファイルを配信する API はありません。
終了はターミナルで `Ctrl+C` を押してください。接続を解放しますが、保存済みセッションは削除しません。
ポートを変更する場合は `$env:PORT = "3001"; npm run ui` を実行します。
起動・取得に失敗する場合は `copilot login` とターミナルのログを確認してください。

## セッション一覧の見方

`sessions` は SDK が接続したランタイムのセッション一覧です。
この環境では CLI (`github/cli`) と VS Code (`vscode-agent-host`) の両方が含まれます。
プルダウンのラベル（概要・クライアント・ID）で見分けてください。
コード側で上位10件などに絞らず、SDK が返す全件を表示しています。
使用中の SDK の `listSessions()` には件数・ページ指定の引数はありません。
VS Code 側のセッションIDと SDK の `sessionId` は異なる場合があります。
プルダウンで選択すると、表示された `sessionId` を使ってセッションを再開します。
別の保存領域・ランタイムで管理されるチャットまで一括取得する API ではありません。

## VS Code 側で作業させる

SDK の `resumeSession()` は Node.js 側で会話を再開するもので、VS Code のチャットへ指示を転送する API ではありません。
ターミナルから VS Code のエージェントへ指示する場合は、VS Code CLI を使えます。

```powershell
code chat --reuse-window --mode agent "モデル一覧とセッション一覧を表示する画面を作って"
```

`--reuse-window` は最後にアクティブだった VS Code ウィンドウを使用します。
特定の既存チャットをセッションIDで指定するオプションではありません。
今話しているチャットを確実に続けたい場合は、そのチャット欄から送信してください。

SDK のストリーミング出力を既存の VS Code Chat 欄に直接追記する API はありません。
後から Chat で参照したい場合は、`app/logs/` の SDK イベントログを添付できます。
以下のパスを対象のログファイルに置き換えて実行してください。

```powershell
code chat --reuse-window --add-file "app\logs\対象のログ.jsonl" "このSDK実行ログを確認して"
```

`code chat` はログをコンテキストとして VS Code 側へ新たな依頼を送る操作です。
SDK の会話をチャット履歴として取り込む操作や、実行中の出力をリアルタイムに追記する操作ではありません。
ログにはコードやツールのエラー情報などが含まれる場合があります。添付前に内容を確認してください。
